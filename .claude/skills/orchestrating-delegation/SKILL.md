# サブエージェント委譲のオーケストレーション

## Overview

指示の質だけでは足りない。**報告は使う前に検証し、設計判断は手元に残し、標準ゲート外には検証を自作する**。
指示文の書き方は `.claude/rules/06-delegation-prompts.md`。

## 5 ステップ

```
① 分解 → ② 指示 → ③ 報告の検証 → ④ 統合 → ⑤ タスク固有検証
```

### ① 分解 — 葉だけ委譲

受入基準とコンテキストを全部文章化できる → 葉。委譲可。
できない（API 契約確定・命名衝突・BE/iOS どちらに置くか）→ コア。手元。
BE と iOS 並列は契約を書き切ってから。

### ② 指示 — 7 要素

`06-delegation-prompts.md` に従う。

### ③ 報告の検証

load-bearing 事実（文言・パス・enum・JSON キー・エンドポイント）を一次ソースで照合。
1 つ誤りなら全数照合へ。詳細 ≠ 正確。

### ④ 統合

複数ワーカー出力の突き合わせと境界確認は自分。BE↔iOS 契約の両端突合は必須。

### ⑤ タスク固有検証

標準ゲートが実行しない変更には使い捨て検証を作り、コマンドと出力を証拠にする。

| 変更 | 例 |
|---|---|
| iOS 振る舞い | 手動確認手順、または Domain 関数の単体実行 |
| BE の DB 依存 | `make up` + curl /health や実リクエスト |
| ドキュメント | 参照 file:line・コマンドの実在 grep |

## よくある間違い

| 間違い | 現実 |
|---|---|
| 詳細報告を信頼して転記 | 抜き取り照合が先 |
| 標準ゲート通過 = 完了 | そのゲートは変更を実行したか |
| コア判断まで委譲 | 差し戻しで遅くなる |
| HEAD だけで照合 | 正は working tree |
