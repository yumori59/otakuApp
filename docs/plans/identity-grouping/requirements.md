# identity-grouping — Requirements

名義一覧を **FC / アーティスト名で自動グルーピングして表示する**。

- 前提となる論点と暫定回答: `questions-requirements.md`（Q1=A / Q2=B / Q3=末尾に「FC未登録」/ Q4=A / Q5=そのFCの会員情報基準 / Q6=名義一覧のみ / Q7=ロードマップに 0-4b を追記）
- **未回答のまま計画を進めている**ため、回答が上記と異なった場合は本ファイルと `plan.md` を先に直す
- 2026-08-20 のユーザー選択で「FC/アーティスト名で自動グルーピング」に確定（ユーザー定義の自由ラベル方式は不採用）

## 1. 用語の確定

| 要望の語 | 実体 | 根拠 |
|---|---|---|
| 「FC」「アーティスト」 | `Membership.fanClubNameRaw`（自由入力文字列）。マスタ表 `fan_clubs` は Phase 1 未実装で `fan_club_id` は API が受理しない | `schema.prisma:130` / `docs/03-database.md:264-287` / `docs/04-api.md:229` |
| 「名義」 | `Identity` | `schema.prisma:103-127` |
| 「グループ」 | 正規化した FC 名をキーとする**表示上の束ね**。DB にもドメインモデルにも新しい永続概念は作らない | 本計画 D-1 |
| 「グループ内の行」 | `(Identity, Membership)` のペア（FC未登録グループのみ `Membership` が nil） | 本計画 D-2 |

## 2. 機能要件

| ID | 要件 |
|---|---|
| FR-IG-1 | 名義一覧（`IdentityListView`）は名義を FC 名でグルーピングして表示する。グループ見出しに FC 名と件数を出す |
| FR-IG-2 | 複数 FC に所属する名義は、**所属する全グループに重複して現れる**（Q1-A）。行は「名義 × 会員情報」 |
| FR-IG-3 | FC 名の同一判定は、前後トリム + 連続空白の 1 個への圧縮 + 全角/半角同一視 + 大文字小文字同一視 で行う。**濁点・ひらがな/カタカナは同一視しない**（Q2-B） |
| FR-IG-4 | グループの表示名は、そのキーで最初に出現した会員情報の `fanClubNameRaw` の**原文**を使う。入力文字列を書き換えて保存することはしない |
| FR-IG-5 | 会員情報が 1 件も無い名義は「FC未登録」グループに入れ、**常に最後**に置く（Q3） |
| FR-IG-6 | グループの並び順は「そのグループ内で最も近い `renewalOn`」の昇順。未設定（nil のみ）のグループは末尾寄せ、同値は表示名の辞書順。「FC未登録」はこの並びに関与せず常に最後 |
| FR-IG-7 | グループ**内**の並び順は既存の 3 種ソート（更新が近い順 / 当選が多い順 / 入会が古い順）を適用する。セグメンテッドコントロールはそのまま残す（Q4-A） |
| FR-IG-8 | 「更新が近い順」でグループ内を並べるときの基準は、名義横断の最小値ではなく**その行の会員情報の `renewalOn`** とする（Q5） |
| FR-IG-9 | 行に出す更新バッジは、その行の会員情報の `renewalOn` を基準にする。FC未登録グループの行はバッジを出さない |
| FR-IG-10 | 同一名義が同一 FC に会員情報を 2 件以上持つ場合（重複登録）は、グループ内で 1 行に畳む。採用するのは `renewalOn` が最も近い方（nil は最劣後） |
| FR-IG-11 | 名義が 0 件のときの空状態は現状のまま（`EmptyStateView`）。グループ見出しは出さない |
| FR-IG-12 | 行タップの遷移先は現状どおり `AppRoute.identity(identity.id)`。同じ名義がどのグループから開かれても同じ詳細画面に行く |
| FR-IG-13 | 未ログイン（ゲスト）時の挙動は現状のまま（`SignInPromptCard` のみ表示、グルーピングは行わない）（`IdentityListView.swift:84-94`） |

## 3. 非機能要件・制約

| ID | 内容 |
|---|---|
| NFR-1 | **BE・DB・API 契約は変更しない**。グルーピングは iOS のローカル計算で完結する（D-1） |
| NFR-2 | グルーピングと正規化のロジックは `Domain` の純粋関数に置き、`swift test --package-path meigicho/Packages/Domain` で検証する（`Domain/Tests/DomainTests/` は稼働中の実テスト。`docs/plans/STATUS.md:135-137`） |
| NFR-3 | `Domain` に SwiftData / SwiftUI を持ち込まない。`Features` は `DataStore` / `Networking` を直接参照しない（IOS-5） |
| NFR-4 | 広告枠の規約を変えない。`PlacementAdSlot(placement: .identitiesBottom)` は**画面最下部に 1 枚のまま**。グループごとに挿入しない（`docs/07-monetization.md` §7.2 F2-2） |
| NFR-5 | 一覧は `List` へ作り替えない（`ScrollView` + `CardList` + `ForEach` を維持）。`delete-ui` 計画が同じ制約下で走っており、一覧の構造変更は衝突する |
| C-1 | FC マスタ（`fan_clubs` / `fan_club_id`）は使えない。文字列キーでのグルーピングであることは `docs/03-database.md:417-425` が一度却下した方式なので、正規化（FR-IG-3）と「原文を保持する」（FR-IG-4）で緩和するに留める |
| C-2 | 名義の追加・編集・削除の導線は変更しない（`delete-ui` / 別計画のスコープ） |
| C-3 | 本機能は `docs/09-roadmap.md` に無い新規スコープ。ロードマップに 0-4b を追記して工数を可視化する（Q7） |

## 4. スコープ外

- ホーム画面・ツアー表・共有ボード・共有プレビューへのグルーピング適用（Q6）
- FC マスタ表の実装、名寄せ UI、FC 名のリネーム一括反映
- グループの折りたたみ / 展開状態の永続化
- ユーザー定義のグループラベル（2026-08-20 のユーザー選択で不採用）
- グループ単位の共有・エクスポート
- 名義・会員情報の削除 / 編集 UI（別計画）

## 5. 受入基準

| AC-ID | 受入基準 | 検証方法 |
|---|---|---|
| AC-IG-01 | 1 FC のみの名義は、そのFCのグループに 1 行だけ現れる | DomainTests |
| AC-IG-02 | 2 FC に所属する名義は 2 グループに現れ、行の合計は会員情報の件数と一致する | DomainTests |
| AC-IG-03 | 会員情報が無い名義は「FC未登録」グループに入り、そのグループは配列の最後にある | DomainTests |
| AC-IG-04 | `"STELLARIS FC"` / `" stellaris fc "` / `"ＳＴＥＬＬＡＲＩＳ　ＦＣ"` は同一グループになり、表示名は最初に出現した原文になる | DomainTests |
| AC-IG-05 | `"ハルカ"` と `"バルカ"`、`"あいうえお"` と `"アイウエオ"` は**別グループ**になる | DomainTests |
| AC-IG-06 | グループ順は、グループ内の最小 `renewalOn` 昇順。全て nil のグループは（FC未登録より前で）末尾寄せ、同値は表示名の辞書順 | DomainTests |
| AC-IG-07 | 「FC未登録」グループは、そのグループの並び基準に関わらず常に最後 | DomainTests |
| AC-IG-08 | ソート「更新が近い順」で、複数FCに所属する名義の位置がグループごとに変わる（そのFCの `renewalOn` が基準になっている） | DomainTests |
| AC-IG-09 | ソート「当選が多い順」「入会が古い順」はグループ内で従来と同じ順序になる | DomainTests |
| AC-IG-10 | 同一名義が同一FCに 2 件の会員情報を持つとき、グループ内は 1 行。採用されるのは `renewalOn` が近い方 | DomainTests |
| AC-IG-11 | 会員情報が 1 件も無い状態（全名義が未登録）で、グループは「FC未登録」1 つだけになる | DomainTests |
| AC-IG-12 | 名義タブを開くと FC 名の見出しごとに名義が束ねられて表示される | 手動確認 |
| AC-IG-13 | 行をタップすると、どのグループからでも同じ名義詳細が開く | 手動確認 |
| AC-IG-14 | セグメンテッドコントロールを切り替えると、グループの中身の並びが変わる（グループ自体は消えない） | 手動確認 |
| AC-IG-15 | 広告バナーは画面最下部に 1 枚のみで、グループとグループの間には出ない | 手動確認 |
| AC-IG-16 | 未ログイン時は従来どおりログイン案内カードだけが出る | 手動確認 |
