# Rule 06: サブエージェント委譲プロンプト

Agent ツールで `nest-developer` / `swift-developer` / Explore / `code-reviewer` 等へ委譲するときの
**プロンプトの書き方**を定める。誰を呼ぶかは `02-agents.md`。

## 3 つの原則

1. **サブエージェントは会話コンテキストゼロで起動する** — 絶対パス・決定事項・制約を指示文に書き写す
2. **出力仕様が品質を決める** — 何を・どの粒度で・どの形式で返すかを構造で指定する
3. **途中で質問できない前提で書く** — 迷い分岐は判断ルールを先に与える

## 指示テンプレート (7 要素)

| # | 要素 | 書くこと |
|---|---|---|
| 1 | **目的/背景** | 何のためか。出力の使われ方 |
| 2 | **対象** | リポジトリ絶対パス + 対象ディレクトリ |
| 3 | **やること** | 番号付き。1 項目 = 検証可能な作業 |
| 4 | **従うべき既存例** | 平仄の file:line |
| 5 | **制約・やらないこと** | スコープ外、`feedback_review_patterns.md` の番号 |
| 6 | **完了条件** | `CLAUDE.md` の検証ゲート |
| 7 | **報告フォーマット** | 日本語、①変更 ②検証結果 ③残課題、file:line |

**1・2・7 は必須**。

## 役割別の追記

### 調査系

- 冒頭に「まず `.claude/skills/investigating-thoroughly/SKILL.md` を読み従う」
- 報告項目を名詞で列挙。file:line 付き・日本語

### 実装系

- BE: 受入基準を失敗する `*.spec.ts` に翻訳してから実装 (Red→Green)
- 既存例を file:line で最低 1 つ指名
- API 契約をまたぐなら契約を指示文に書き切ってから委譲
- 同一ファイル（特に `schema.prisma`・`app.module.ts`・ApiClient）を 2 人に触らせない

### レビュー系

- 差分範囲を明示（staged / main...HEAD）
- 結果の保存先（`docs/plans/<feature>/review.md`）
- スコープ外を再掲して無駄な指摘を防ぐ

## 委譲後のオーケストレーター責務

実体は `orchestrating-delegation` skill:

1. 報告の load-bearing 事実を一次ソースで抜き取り検証
2. 葉だけ委譲（API 契約の確定は手元）
3. 標準ゲートが効かない変更にはタスク固有検証を用意
