## Q1. 複数FCに所属する名義をどのグループに出すか

F2 のとおり 1 名義 = 1 FC ではない。

| 選択肢 | 内容 | 影響 |
|---|---|---|
| A | **所属する全グループに重複表示**（行 = 名義 × 会員情報） | 「このFCで使える名義はどれか」を必ず引ける。行数 ≠ 名義数になるので件数表示の説明が要る |
| B | 代表 1 件のみ（最も更新が近いFC等） | 行数 = 名義数で直感的。ただし他FCの所属が一覧から消える（情報欠落） |
| C | 「複数FC」という別グループを作る | 「STELLARIS の名義」を探すと複数所属の名義が出てこない。用途に反する |

- **デフォルト仮定: A**
- 理由: 一覧の用途は「このFCの申込に使う名義を引く」こと。B / C はその用途を壊す。
  重複による混乱は、グループヘッダに件数を出し、画面上部に実名義数を出すことで緩和する。

## Q2. FC 名の同一判定（表記ゆれをどこまで吸収するか）

F3 のとおりマスタが無いので**文字列がキー**になる。F8 の警告が直接効く論点。

| 選択肢 | 内容 |
|---|---|
| A | 完全一致（原文そのまま） |
| B | **前後トリム + 連続空白の圧縮 + 全角/半角同一視 + 大文字小文字同一視**（濁点・カナ種別は同一視しない） |
| C | B + マスタ表（`fan_clubs`）を実装して名寄せする |

- **デフォルト仮定: B**
- 理由: A は「STELLARIS FC」と「STELLARIS　FC」（全角空白）が別グループになり、F8 の分裂がそのまま起きる。
  C はマスタ表・名寄せ UI・BE 実装を伴い、Phase 1 の未実装項目（F3）を引き受けることになるので本計画のスコープ外。
  濁点・ひらがな/カタカナの同一視（`.diacriticInsensitive` / kana folding）は**採らない**。
  「ハルカ」と「バルカ」を同じFCに畳むのは誤結合で、利用者が自力で直せない。
- 表示名は**そのキーで最初に出現した会員情報の原文**を使う（原文を勝手に書き換えない）。

## Q4. 既存の 3 種ソートとの関係

グルーピングとソートは直交する概念（グループの並び順 / グループ内の並び順）。

| 選択肢 | 内容 |
|---|---|
| A | **常時グルーピング表示にし、既存 3 ソートはグループ内の並び順として残す** |
| B | セグメントに 4 つ目「FC別」を足す（＝ソートの 1 種として扱う） |
| C | 「一覧 / FC別」の表示モードトグルを追加し、既定はフラット一覧のまま |

- **デフォルト仮定: A**
- 理由: B はグループ内順序を決める手段が無くなる（ソートは 1 つしか選べない）。
  C は既定オフなので、要望された機能に誰も辿り着かない（IOS-1 に近い死に方をする）。
- グループの並び順は F9 の先例に合わせ「グループ内の最も近い更新日」昇順、未設定は末尾、同値は表示名順。

## Q5. グループ内の行に何を出すか（更新バッジの基準）

F7 のとおり、現在のバッジは全FC横断の最小 `renewalOn`。FC 別グループの中では誤解を生む
（STELLARIS のグループに並んでいるのに、バッジが別FCの更新日を指す）。

- **デフォルト仮定: グループ内の行は「そのFCの会員情報」を基準にする**
  - 更新バッジ = その `membership.renewalOn`
  - subtitle = FC 名連結（現状）ではなく、その会員情報の情報（ランク / 年会費）に置き換える
  - meta（入会日・当選回数）は名義単位のまま変えない
- 理由: グループの文脈で名義横断の値を出すのは事実として誤り。ここは修正機会でもある。
