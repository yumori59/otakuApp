## 2. 認証方針（モックとの差分の扱い）

モックは Google / メールPW のみ。App Store で第三者ログインを出す場合は Sign in with Apple がほぼ必須（Guideline 4.8）。

| プロバイダ | Phase 0 | Phase 1 | 備考 |
|------------|---------|---------|------|
| （なし・ローカル） | ○ | — | 既存方針維持 |
| **Sign in with Apple** | — | **必須** | NestJS が identity token 検証 → 自前 JWT |
| Google | — | 任意 | モック反映。入れるなら Apple 必須 |
| メール+パスワード | — | 任意（推奨度低） | リセット・漏洩対策コスト増。初期は見送ってもよい |

アカウントID / ユーザーネーム / 背景カラー / アプリ表示名は、Apple ログイン後の `profiles` に載せる。

## 3. 共有モデルの整理（**2026-08-07 に再決定・確定**）

モックは次の2層が混在していた。

1. **URLを知っている人は閲覧・編集できる**（実質オープンボード）
2. **共有相手のアカウントIDは記録用**（アクセス制御ではないと UI が明記）

この 2 層をどう畳むかを「Phase 2 で再決定する」として保留していたが、**2026-08-07 にユーザー決定で確定した**。

### 決定: アカウント招待制へ完全移行する

| 項目 | 決定 |
|------|------|
| 認可 | **招待されたアカウントだけ**が閲覧・編集できる。トークンの有効性だけでは通さない |
| ACL の実体 | **`share_recipients` テーブル**（`share_link_id` × `account_id` / `user_id`）。招待は 1〜20 件で**必須** |
| 公開経路 | `GET/PATCH /public/shares/:token` を**完全廃止**（ルートごと削除）。未ログイン閲覧は不可能になる |
| 受け取り側の導線 | **アプリ内の受信箱**（`GET /v1/shares/received`）。トークン URL を個別に受け取らなくても、ログインすれば自分宛ての共有が一覧で見える |
| 非招待者 | トークン提示 → **403 `SHARE_NOT_INVITED`** / 共有 ID 提示 → 404 `SHARE_INVALID`（存在を confirm しない） |
| `shared_with_account_ids` | **カラムごと削除**。「記録用メタ」という概念は無くなった |
| 既存の共有リンク | **全件失効**（`revoked_at`）。作り直しは新スキーマで行う |
| 承諾フロー | 無し。招待された時点で受信箱に出る。受け取り側は「非表示」にできる（オーナーには見せない） |

**この決定でトレードオフしたもの**: `09-roadmap.md` の成長仮説③「共有リンクがそのまま招待になる（アプリ未導入の受け手にも見せられる）」と
KPI「共有リンク経由の新規インストール比率 ≥ 10%」は、公開経路の廃止により達成できなくなる。
「基本的にアカウントを持っている人どうしの機能にしたい」というプロダクト方針を優先した結果であり、
**KPI の再設定は `09-roadmap.md` 側の残課題**とする。

計画・契約・受入基準の正: **[`./plans/share-account-invites/`](./plans/share-account-invites/)**
（`requirements.md` / `api-contract-delta.md` / `plan.md`）。

## 4. データモデル追加（要約）

```
profiles
  + account_id          text unique   -- ACC-XXXXXX（公開用ショートID）
  + username            text          -- 表示名
  + app_display_name    text          -- ホーム見出し（既定: 参戦名義帳）
  + theme_color         text          -- アプリ背景テーマ（名義 color とは別）
  + email               text null     -- メール/Google 利用時
  + auth_providers[]                  -- apple / google / email

identities.color                    -- 名義カラーのみ（テーマ非連動）

share_links
  (shared_with_account_ids text[] は 2026-08-07 に削除 — §3 の再決定)

share_recipients                    -- ★ACLの実体（2026-08-07 追加）
  share_link_id uuid                -- → share_links
  account_id    text                -- ACC-XXXXXX（招待時のスナップショット）
  user_id       uuid                -- 解決済み users.id。判定はこちらで行う
  hidden_at     timestamptz null    -- 受け取り側が非表示にした（オーナーには見せない）
  last_viewed_at timestamptz null   -- 未読判定
  unique (share_link_id, account_id) / index (user_id)

applications.status                 -- draft をUIでも正式対応（モック反映済）
application_companions              -- UI上限 3
```
